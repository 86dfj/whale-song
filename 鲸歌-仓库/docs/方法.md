# 方法说明

## 一、为什么用抓包

想测服务器发包节奏，有两条路：

1. 读游戏内存 / 注入——**会碰反作弊，也会改游戏**
2. 只看网络——**不碰游戏，只看时间戳**

鲸歌走第二条。

## 二、原理

服务器状态包如果是等间隔的，序列在频域会有一根尖峰：

- 峰值位置 → 频率（每秒几批）
- 峰的形状 → 抖动

为了不依赖单一算法，鲸歌同时用四种方法：

1. 频谱峰值
2. 自相关
3. 间隔统计（中位数 / 众数）
4. 多路一致性检查

四种结果对不上时，结论降级为 `参考` 或 `不可判`。

## 三、可信度分级

| 等级 | 条件 |
|---|---|
| 可信 | 至少三种算法一致，且显著性够高 |
| 参考 | 两种一致，或样本偏少 |
| 不可判 | 流太杂、抖动太大、样本不足 |

## 四、验证方式

| 测试 | 做法 | 结果 |
|---|---|---|
| 闭环 | 自己造已知频率的流 | 误差 0.0% |
| 真值 | 故意丢 10% / 20% 的包 | 估出 10.2% / 20.9% |
| 对抗 | 6 种伪造节奏 | 全部识别 |
| 回归 | 17 项固定用例 | 全过 |

## 五、已知边界

- 批 ≠ 引擎 tick
- 多路复用不可判
- 10 秒内的变化看不见
- 缺包偏高（含网络丢包 + 服务器少发）
