## 一、这是什么

**鲸歌**：Windows 桌面工具，被动抓包测游戏服务器的发包节奏（tick 近似）。

- 不注入、不读内存、不改游戏，只用 Windows 自带 pktmon 看时间戳
- 输入：一局游戏的 pcapng（约 30–60 分钟）
- 输出：`report.md`（报告）、`tick.png`（图）、`report-brief.md`（一页简报）、`evidence.json`（哈希与参数）

**一句话定位**：不是外挂，是「给服务器测心跳的仪器」。

## 四、数据管线

```
pktmon 抓包
  → network.etl
  → (停止时) etl2pcapng → network.pcapng
  → analyze.read_capture / parse_packet：逐包解析 (ts, src, sport, dst, dport, len)
  → tickcore.load_flows：按 5 元组建 UDP 流，时间戳排序
  → tick_report.collect_segments：挑出「对局段」
  → 每段估 tick / 丢包 / 抖动
  → 生成报告 + 图 + 证据
```

**关键事实**：pktmon 会重复抓包（实测 2–6 倍），所以「包数/包/秒」偏高，**tick 不受影响**（副本落在同一簇里）。

## 五、算法细节（tickcore）

### 1. 频谱法
- 对到达时间序列做 FFT，找 5–130 Hz 内的主峰
- 主峰位置 = tick 估计
- 显著性 `snr` = 峰值能量相对均匀分布的倍数；随机流约 10–14，>100 清晰

### 2. 窗口法（tick_series）
- 10 秒一个窗口，逐窗估 tick、抖动、丢包
- 窗口值用「簇聚类」+ 抖动修正
- 用于画图、速率变化检查、持续性判断

### 3. 四种交叉验证
频谱 / 自相关 / 间隔统计 / 多路一致性；不一致就降级「参考」或「不可判」。

### 4. 谐波解析
频谱主峰可能是 2×/3× 谐波（大战场实测：50 其实是 25 的二次）。
检测到谐波时按基频计，并在报告里写明。

### 5. 一 tick 分两批
间隔「长短交替」（lag-1 自相关 < -0.65）时，真实 tick 是当前值的一半。
报告会标注「疑似一 tick 分两批发」，不自动改主值。

### 6. 多路复用
多条逻辑流摊平在一条 UDP 流里 → 单流节奏被摊平 → 判「不可判」。
此时报告给「间隔主峰」参考值（明确标注不是结论）。

### 7. 丢包
`loss = 按节奏反推的缺失比例`，含网络丢包 + 服务器主动少发/合包。
**天然高于游戏内显示**（客户端按序列号算的链路丢包）。

### 8. 卡顿
`卡顿归因.scan`：找 ≥2 秒的包间隔，判断「服务器没发」还是「本地链路中断」。

### 9. 完整性
时间戳单调性、大空洞、文件结构；用于证明抓包没被截断。

## 六、对局段判定（大厅 vs 对局）

四道门槛同时满足：

| 条件 | 阈值 |
|---|---|
| tick 范围 | 10–130 Hz |
| 缺包率 | < 40% |
| 持续 | ≥ 60 秒 |
| 显著性 | 有周期峰（非随机） |

- 大厅心跳 1–5 Hz → 被频率范围排除
- 切页/加载 → 时长不够
- 商店/网页 → 无周期
- **风险**：大厅挂机 60 秒以上且服务器稳定发包，可能被误判成一段
- 换服务器 IP → 算新段，不合并

## 八、游戏识别

三个信号源（identify.py）：

1. **DNS 明文查询**（UDP 53）——最可信
2. **TLS SNI**——TCP 握手里的服务器名
3. **IP 段 + 自定义映射**——兜底

自定义映射：`games.json`（域名关键词 → 游戏），用户标注会写进这里。
合并规则（`合并标注.py`）：新关键词需 **≥5 票且 ≥60% 一致**；本地已有的免票。

已收录：`val.qq`/`valorant`→无畏契约，`df.qq`/`deltaforce`→三角洲，`klbq`/`strinova`→卡拉彼丘，`csgo`/`counter-strike`→CS2，`wzry`→王者荣耀 等。

**外服识别较弱**：Riot 外服域名不区分游戏，只能靠用户标注。

## 十、双语实现（重要，改文字必读）

不是逐行 if/else，而是**翻译层 + 短语表**：

1. `i18n.en(text)`：lang=en 时按「最长短语优先」替换，另有正则兜底
2. 报告出口：`tick_report.py` 写盘前后调用
3. GUI：`_install_en_shim()` 包装控件构造、`configure(text=)`、messagebox、Toplevel.title、simpledialog
4. 控制台：`i18n.wrap_stdout()` 包装 stdout
5. 图表：`render()` 里用 `_png_tr` 包标题/图例/轴标签

**改中文文案时，必须同步更新 `en_phrases.py` / `en_app_phrases.py` 里对应 key**，否则英文界面会漏中文。
**不要翻译**：解析用的正则、`可信/参考/不可判` 等比较键、文件名。

## 十三、已知边界与坑

1. **批 ≠ 引擎 tick**：被动抓包分不出「每秒几个包」和「每秒几帧模拟」
2. **多路复用必判不可判**：竞技 FPS 常态
3. **10 秒以内的变化看不见**
4. **pktmon 重复抓包**：包数偏高，别引用
5. **settings.json 带 BOM 会读不出**：必须 Python 写（无 BOM）
6. **tick.png 被看图软件占用**时重新出报告会失败：关掉预览
7. **内嵌 Python 不把脚本目录加 sys.path**：app.py 手动 `sys.path.insert(0, ROOT)`
8. **VERSION.txt 的 channel 决定标题**：dev 带「开发者版」
9. **打包用 `打包.py`**，不要手工 zip（会混 `__pycache__`、channel 错）
10. **报告里的数字全部可复现**：pcap + 脚本 + 参数 = 同一个数
